03 詳細設計 · 03/03

単体テスト観点

撮るほどの単体テスト観点を正常系・異常系・境界値で整理する。単体テストは詳細設計（処理・テーブル）に対応する（V 字）。

確定メモ

本表は AI／開発者が単体テストコードを生成する際のインプットである。観点は「入力条件 → 期待結果」で検証可能に書く。

外部 Claude・Blob はモックする。DB はテスト用 libSQL／インメモリまたはトランザクションロールバックを用いる。

配置の目安: src/**/__tests__ または src/**/*.test.ts（プロジェクトのテストランナー規約に従う）。

観点整理の方針

  • 各モジュールの分岐・バリデーションを正常系・異常系・境界値で洗い出す。
  • 受け入れ基準・処理設計の failed/partial・所有境界と対応させる。
  • UI コンポーネントの見た目は本表の主対象外。純関数・Server Action・リポジトリ層を優先する。

観点表

ID 機能 区分 観点（入力条件 → 期待結果）
UT-01 AI JSON パーサ 正常系 必須フィールド完備・failed=false・partial=false の JSON → パース成功。title / easyText / detailText / easyRuby / detailRuby / aiNote / ocrRaw が得られる
UT-02 AI JSON パーサ 正常系 failed=true（他フィールド空可）→ 結果種別 failed。partial は false に正規化
UT-03 AI JSON パーサ 正常系 partial=true・partialChars あり・解説フィールドあり → 結果種別 partial。バナー用 partialChars 保持
UT-04 AI JSON パーサ 異常系 failed=true かつ partial=true → failed 優先に正規化（partial を落とす）
UT-05 AI JSON パーサ 異常系 JSON でない文字列・フェンス付き Markdown のみ → パース失敗（failed 相当またはエラー）
UT-06 AI JSON パーサ 異常系 failed=false なのに title または easyText 欠落 → バリデーションエラー／failed 扱い
UT-07 AI JSON パーサ 境界値 partial=true かつ partialChars=null または空文字 → partial は受理し partialChars は null 正規化（または警告付き受理）
UT-08 AI JSON パーサ 境界値 未知プロパティ付き JSON → 既知フィールドのみ採用し成功（前方互換）
UT-09 ルビ HTML サニタイズ 正常系 <ruby>漢字<rt>かんじ</rt></ruby> のみ → そのまま残る
UT-10 ルビ HTML サニタイズ 異常系 <script>・onclick 等 → 除去され実行可能残骸なし
UT-11 ルビ HTML サニタイズ 異常系 <a href>・<img> 等の非許可タグ → 除去またはエスケープ
UT-12 ルビ HTML サニタイズ 境界値 空文字・プレーンテキストのみ（ruby なし）→ 安全にそのまままたはエスケープして返る
UT-13 ルビ HTML サニタイズ 境界値 入れ子の不正 ruby / 未閉じタグ → クラッシュせずサニタイズ結果を返す

UT-20 record の userId スコープ 異常系 未認証で list / save / memo → UNAUTHORIZED
UT-21 record の userId スコープ 正常系 INSERT 時 userId はセッションから付与。クライアント指定 userId は無視または拒否
UT-22 位置情報 null 時の表示分岐 正常系 lat/lng 両方あり → 地図ピン対象に含まれる。メタに placeName があれば表示
UT-23 位置情報 null 時の表示分岐 正常系 lat/lng 両方 null → 履歴一覧には出るが地図ピン対象外。結果メタは日時のみ／「場所は記録されていません」
UT-24 位置情報 null 時の表示分岐 境界値 lat のみ非 null・lng null → 両方 null に正規化（またはピン対象外）。片肺でピンしない
UT-25 位置情報 null 時の表示分岐 境界値 記録はあるが全件座標なし → 地図はピン 0 件用メッセージ（位置オフ配慮）
UT-26 同ユーザー履歴ソート 正常系 同一 userId で createdAt が異なる複数件 → createdAt 降順（新しい順）
UT-27 同ユーザー履歴ソート 境界値 0 件 → 空配列。例外にしない
UT-28 同ユーザー履歴ソート 境界値 ホーム用 limit=3 → 最新 3 件のみ。全体件数とは独立
UT-29 メモ更新 正常系 所有 record に memo 文字列 → 更新成功。再取得で一致。履歴「メモあり」判定が true
UT-30 メモ更新 正常系 memo を空文字で更新 → null 正規化（または空）。「メモあり」は false
UT-31 メモ更新 異常系 他ユーザー record の memo 更新 → NOT_FOUND。元 memo 不変
UT-32 メモ更新 境界値 最大長超過（実装上限）→ バリデーションエラー
UT-33 削除 cascade 的振る舞い 正常系 データ全削除 Action → 当該 user の records が 0 件。他 user の records は残る
UT-34 削除 cascade 的振る舞い 正常系 全削除後 user_settings は既定値（または再作成後の既定）。users 行は残存
UT-35 削除 cascade 的振る舞い 異常系 確認フラグなしの全削除要求 → 拒否。データ不変
UT-36 削除 cascade 的振る舞い 正常系 users 削除（退会相当の FK テスト）→ 紐づく records / user_settings / sessions が CASCADE で消える
UT-37 スキャン状態機械 正常系 合法遷移 idle→capturing→ocr→generating→done が受理される
UT-38 スキャン状態機械 異常系 禁止遷移 idle→generating / failed→done が拒否または no-op
UT-39 結果 mode / furigana 正常系 mode=easy, furigana=on → easyRuby を選択。off → easyText
UT-40 結果 mode / furigana 正常系 mode=detail, furigana=on → detailRuby。設定初期値が modeDefault/furiganaDefault から入る

網羅の目安

区分最低限カバーする内容
正常系撮影結果パース成功、記録保存、履歴ソート、設定既定、メモ更新、地図ピン対象判定
異常系JSON 不正、他ユーザーアクセス、未認証、禁止状態遷移、未確認全削除
境界値partialChars 空、座標片肺、0 件一覧、メモ空、ruby なしプレーン

モック方針

  • Claude API: 固定 JSON フィクスチャ（成功／failed／partial／壊れた本文）。
  • Vercel Blob: put/del をモックし URL 文字列のみ返す。
  • Geolocation: 単体では lat/lng 引数を直接渡し、ブラウザ API は結合以降。
  • 時刻: createdAt ソート検証時は固定クロックまたは明示タイムスタンプ挿入。
