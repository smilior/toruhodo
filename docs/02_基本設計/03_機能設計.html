02 基本設計 · 03/07

機能設計書

撮るほどの各機能を外部から見た振る舞いとして定義する。Google ログイン必須・ユーザー単位で Turso と Blob に永続化。

確定メモ

内部アルゴリズムの詳細は 03_詳細設計/01_処理設計 へ。ここでは処理概要・入出力・依存関係を定義する。機能 ID は PRODUCT_BRIEF の F-00〜F-09 に対応する。

機能一覧

機能ID 名称 主画面 依存
F-00Google ログイン / ログアウトS-00Better Auth / GCP
F-01ホーム（かざして解説・さいきんの記録）S-01Auth / records 読取
F-02撮影（カメラ・ギャラリー・フラッシュ UI）S-02端末カメラ / ファイル
F-03OCR＋AI 解説生成S-02→S-03/S-04Claude Vision / Blob

F-00 Google ログイン / ログアウト

  • 処理概要 — Better Auth 経由で Google OAuth にサインインする。セッション Cookie を発行。ログアウトでセッション破棄。
  • 入力 — ユーザーの Google アカウント選択。
  • 出力 — 認証済みセッション。成功後はホーム（S-01）へ。
  • 依存 — Better Auth、/api/auth/*、GCP OAuth クライアント。
  • 受け入れ — 未ログインで保護ルートに入ると S-00 へ。ログイン後は自分のデータのみ見える。

F-01 ホーム

  • 処理概要 — 「かざして解説」CTA と、直近の旅の記録カードを表示する。
  • 入力 — セッション userId。任意で records 件数制限（例: 2〜3 件）。
  • 出力 — 直近 records（title, photoUrl, createdAt, placeName, memo 有無）。
  • 依存 — Auth、records 読取（F-09）。
  • 受け入れ — CTA 1 タップで撮影画面へ。「すべて見る」で履歴へ。

F-02 撮影

  • 処理概要 — カメラプレビュー、シャッター、ギャラリー選択、フラッシュ UI を提供する。ガイド枠・ヒントピルを表示。
  • 入力 — カメラ映像または画像ファイル。
  • 出力 — 撮影／選択した画像バイナリ（クライアント保持後 F-03 へ）。
  • 依存 — 端末 MediaDevices / file input。位置情報は geoEnabled 時に取得試行（任意）。
  • 受け入れ — 閉じるでホームへ。シャッター後はローディング（1d）へ遷移。

F-03 OCR＋AI 解説生成

  • 処理概要 — 画像をサーバーへ送り Blob へ格納し、Claude Vision に 1 リクエストで OCR＋解説 JSON を生成させる。状態: ocr → generating → done | failed | partial。
  • 入力 — 画像、任意 lat/lng/placeName。
  • 出力 — AI 契約 JSON（failed, partial, partialChars, ocrRaw, title, easyText, detailText, easyRuby, detailRuby, aiNote）および photoUrl。
  • 依存 — Claude Vision（AI）、Vercel Blob、Auth。
  • 受け入れ — failed 時は F-05 失敗 UI。partial 時は注意バナー付き結果。成功時は結果画面へ。

F-04 解説結果

  • 処理概要 — 写真・タイトル・メタ・モード切替・ふりがな・原文カード・AI補足カード・メモ・記録に残す・免責を表示する。
  • 入力 — スキャン結果または保存済み record id。settings の modeDefault / furiganaDefault を初期値に。
  • 出力 — 画面ローカル mode / furigana。保存時は saveRecord / updateMemo。
  • 依存 — records、user_settings。本文切替は即時（〜200ms fade）。
  • 受け入れ — やさしい⇄くわしい、ふりがな ON/OFF が即時反映。免責が常時表示。

F-05 読み取り失敗・部分読み取り

  • 処理概要 — failed: 責めない失敗画面（コツ 3 項目・再撮影・ホーム）。partial: 結果画面上部バナー＋読めた文字チップ＋「もう一度撮る」「このまま記録に残す」。
  • 入力 — AI の failed / partial / partialChars。
  • 出力 — 再撮影遷移、または partial のまま保存。
  • 依存 — F-03 の結果フラグ。
  • 受け入れ — 失敗文面が落胆させないトーンであること。

F-06 旅の記録（履歴）

  • 処理概要 — ユーザーの records を新しい順に一覧。空状態では CTA で撮影へ。
  • 入力 — userId。
  • 出力 — カード（サムネイル・title・日付・場所・メモありバッジ）。
  • 依存 — records 読取。場所は lat/lng がある場合のみ表示。
  • 受け入れ — タップで結果画面（保存版）。件数表示。

F-07 旅の記録地図

  • 処理概要 — MapLibre で地図を描画し、位置付き records をピン表示。タップでポップアップ→結果画面。
  • 入力 — lat/lng が非 null の records。geoEnabled 状態。
  • 出力 — 地図 UI・件数チップ・位置情報オフ時の配慮メッセージ。
  • 依存 — MapLibre（クライアント）、Geo 設定、records。
  • 受け入れ — 位置なし記録はピンに出さない。オフ時もタブは残し導線を出す。

F-08 設定

  • 処理概要 — ふりがな初期値、解説モード初期値、位置情報記録 ON/OFF、データ削除、利用規約／免責への導線。shadcn リスト想定。
  • 入力 — user_settings の更新値。削除確認。
  • 出力 — 更新済み settings。deleteAllUserData 時は records・Blob・設定等の消去。
  • 依存 — user_settings、F-09、認可。
  • 受け入れ — 初期値が結果画面の mode/furigana に反映される。

F-09 クラウド永続化

  • 処理概要 — records を Turso に、写真を Vercel Blob に保存する。読取・更新・削除は userId スコープ。
  • 入力 — Record 属性一式。写真バイナリ。
  • 出力 — 永続化された id と photoUrl。
  • 依存 — Turso / Drizzle、Vercel Blob、Auth。
  • 受け入れ — 他ユーザーの record は不可視。派生値は DB に持たない。

主要フロー（概要）

ログイン(F-00) → ホーム(F-01)
  → 撮影(F-02) → OCR+AI(F-03)
       ├ failed → 失敗UI(F-05) → 再撮影 or ホーム
       ├ partial → 結果(F-04)+注意(F-05) → 保存(F-09)
       └ done → 結果(F-04) → 記録に残す(F-09)
  → 履歴(F-06) / 地図(F-07) / 設定(F-08)
