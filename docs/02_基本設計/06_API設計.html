02 基本設計 · 06/07

API設計書

撮るほどのアプリケーション API。認証は Better Auth の HTTP ルート、ドメイン操作は Server Actions。Claude と Blob は server-only。

確定メモ

公開 REST リソース API は MVP では設けない。クライアントは Server Actions / 必要に応じた Route Handlers 経由。Claude API キーと Blob トークンはサーバーのみ。

共通規約

  • 認証 — Server Actions は requireUserId() 等でセッション必須。未認証は UNAUTHORIZED → 「ログインが必要です」。
  • 所有 — records の読取・更新・削除は user_id = session.user.id 必須。未所有は「記録が見つかりません」。
  • 結果型 — ActionResult<T> = { ok: true; data: T } | { ok: false; error: string }
  • 再検証 — ミューテーション後に該当パスを revalidatePath
  • 写真 — アップロード後に Blob URL を受け取り、records.photo_url に保存

Better Auth エンドポイント

パス 概要 備考
/api/auth/*Better Auth ハンドラ全体sign-in / sign-out / session / OAuth callback 等
/api/auth/callback/googleGoogle OAuth コールバックGCP に登録するリダイレクト URI

プロバイダ: Google（GOOGLE_CLIENT_ID / GOOGLE_CLIENT_SECRET）。セッション Cookie 名: better-auth.session_token（Secure 環境では __Secure- 接頭）。

Server Actions 一覧

関数 概要 認証
createScanFromPhoto写真 upload → Blob、Claude で OCR＋解説、結果返却（未保存可）要
saveRecord解説結果を records に永続化要
updateMemo記録のメモ更新要
deleteRecord記録削除（Blob も削除試行）要
updateSettingsuser_settings 更新要
deleteAllUserData当該ユーザーの records・設定等を全削除要
listRecords（任意）履歴・ホーム用一覧要
getRecord（任意）単一 record 取得要

関数名は実装で微調整可。上記は契約上の責務を示す。

個別仕様

createScanFromPhoto

写真を Blob にアップロードし、Claude Vision で解説 JSON を生成する。永続化は saveRecord に分離してもよい（実装選択）。

名前型必須説明
imageFile / base64 / FormData必須撮影画像
latnumber | null任意緯度
lngnumber | null任意経度
placeNamestring | null任意場所名

saveRecord

名前型必須説明
photoUrlstring必須Blob URL
title ほか解説フィールドstring / bool必須AI 契約に準拠
memostring | null任意ユーザーメモ

// 成功
{ "ok": true, "data": { "id": "rec_xxx" } }
// 失敗
{ "ok": false, "error": "ログインが必要です" }

updateMemo

  • 入力: { id: string, memo: string | null }
  • 所有チェック必須
  • 成功: { ok: true }

deleteRecord

  • 入力: { id: string }
  • 所有レコード削除。可能なら Blob も削除
  • 成功: { ok: true }

updateSettings

  • 入力: { furiganaDefault?: boolean, modeDefault?: "easy"|"detail", geoEnabled?: boolean }
  • upsert user_settings
  • 成功: { ok: true, data: UserSettings }

deleteAllUserData

  • 入力: 確認フラグ（クライアントで二段階確認後に呼ぶ）
  • 当該 userId の records 全削除、関連 Blob 削除試行、user_settings リセットまたは削除
  • Auth ユーザー行の削除はプロダクト方針に従う（MVP はアプリデータ削除を優先）
  • 成功: { ok: true }

Claude 呼び出し（internal / server-only）

  • クライアントから Anthropic へ直接呼ばない
  • Server Action または内部モジュール src/lib/ai/* から呼び出し
  • 1 リクエストで Vision 入力＋JSON スキーマ応答

AI レスポンス契約（PRODUCT_BRIEF 準拠）:

{
  "failed": false,
  "partial": false,
  "partialChars": null,
  "ocrRaw": "...",
  "title": "...",
  "easyText": "...",
  "detailText": "...",
  "easyRuby": "<ruby>…</rt></ruby>…",
  "detailRuby": "...",
  "aiNote": "..."
}
  • failed: true → 失敗画面 1h
  • partial: true → 注意バナー＋読めた文字チップ 1i

写真 upload → Blob URL

  1. 認証済みリクエストで画像を受領
  2. Vercel Blob に put（パスに userId またはランダム ID を含め推測困難化）
  3. 返却 URL を photoUrl として利用
  4. 一覧・結果画面ではアプリ経由で URL を埋め込み表示
// 概念
const blob = await put(`toruhodo/${userId}/${id}.jpg`, file, { access: "public" });
// blob.url → records.photo_url

アクセス方針の詳細は 07_認可設計 を参照。
