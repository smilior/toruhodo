02 基本設計 · 07/07

認可設計書

撮るほどの認証・認可方針。個人アカウント単位で旅の記録を分離する。共有アルバムは MVP 外。

確定メモ

ロールは「認証済みユーザー」のみ。管理者画面は MVP に含めない。すべての domain 操作は session.user.id を所有者キーとする。

方針概要

  • 認証: Better Auth + Google OAuth
  • 未ログインは保護ルート不可（S-00 /login へ）
  • 全 record は userId 一致必須
  • 他ユーザーのデータは一覧・詳細・地図ピンのいずれでも不可視
  • Blob URL は推測困難パス ＋ アプリ経由で提示

ルート保護

区分 パス例 条件
公開/login、/api/auth/*未認証可
保護/、/scan、/result/*、/history、/map、/settingsセッション必須。なければ S-00
Server Actionsrecords / settings / scan 系requireUserId() 必須

Middleware でセッション Cookie を検証し、保護ルートへの未認証アクセスを /login にリダイレクトする。ログイン済みで /login に来た場合はホームへ誘導してよい。

データ所有モデル

session.user.id
  ├ records.user_id  ＝ 必須一致（SELECT/UPDATE/DELETE）
  └ user_settings.user_id ＝ 必須一致（upsert/read）
操作 認可ルール 違反時
listRecordsWHERE user_id = session.user.id他ユーザー行は結果に出ない
getRecordid 指定＋ user_id 一致「記録が見つかりません」
saveRecorduser_id はセッションから強制付与（クライアント指定不可）未認証エラー
updateMemo / deleteRecord対象行の user_id 一致同上
updateSettings自 user_id のみ未認証エラー
deleteAllUserData自 user_id の全 records・settings のみ未認証エラー
地図ピン自 records かつ lat/lng 非 null のみ—

Blob URL のアクセス方針

  • オブジェクトキーに十分なエントロピー（userId ＋ ランダム id 等）を含め、推測困難 URL とする。
  • UI ではアプリが所有確認後に得た photoUrl のみを img 等に埋め込む（一覧・詳細は常にアプリ経由）。
  • MVP では Vercel Blob の public URL を用いる場合がある。その場合も URL 列挙を前提としない設計とし、共有リンク機能は提供しない。
  • record 削除時は Blob 削除を試行し、孤児オブジェクトを減らす。
  • 将来強化: プライベート Blob ＋ 署名付き URL やプロキシ配信を検討可（ADR 化）。

シークレットと外部 API

  • ANTHROPIC_API_KEY、BLOB_READ_WRITE_TOKEN、TURSO_AUTH_TOKEN、BETTER_AUTH_SECRET、GOOGLE_CLIENT_SECRET はサーバー環境のみ。
  • クライアントバンドルに秘密情報を埋め込まない。
  • Claude / Blob は Server Actions または server-only モジュール経由。

脅威と緩和（MVP）

脅威 緩和
他ユーザー record ID の直打ち取得時 user_id 一致。不一致は存在秘匿メッセージ
userId のクライアント改ざんサーバーでセッションから付与。入力の userId を信用しない
未認証での Server Action 実行全ミューテーションで requireUserId
API キー漏洩環境変数・server-only。ログにキーを出さない
Blob URL の漏えい推測困難パス。アプリ外共有 UI なし。削除時クリーンアップ

スコープ外（MVP）

  • 複数人・世帯共有、旅の共有アルバム
  • 管理者ロール・監査ログ UI
  • 細粒度 RBAC
